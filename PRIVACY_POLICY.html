Privacy Policy for Kunjika

Effective Date: August 26, 2026
Last Updated: October 19, 2026 (source version 1.9.0, version code 19)

Kunjika is a local-first password manager. The Android app removes the INTERNET permission and does not provide user accounts or cloud synchronization. Bluetooth, QR, clipboard, operating-system integrations, and receiving devices remain data-sharing paths that require your care.

Kunjika does not operate an account, analytics, or cloud-sync service. Device-level services may process information according to their own privacy terms.

1. Accounts, Analytics, and Data Sharing

  • No Android Internet Permission: The app manifest removes the INTERNET permission. The app can still share data over Bluetooth and QR, and copied data may be retained by clipboard integrations.
  • No Analytics: Kunjika does not include third-party analytics, tracking, or crash-reporting SDKs.
  • No Cloud Storage: Kunjika does not operate cloud synchronization servers. Vault contents are stored locally unless you choose to copy, export, or transfer selected data.

2. Data Encryption

Vault protection uses SQLCipher and Android Keystore, with additional AES-GCM encryption for password and TOTP-secret fields. Hardware backing depends on the device:

  • At Rest: Password and TOTP-secret fields use AES-256-GCM with Android Keystore keys. The database uses SQLCipher with a random passphrase wrapped by Android Keystore. Other metadata is protected by database encryption, not separately field-encrypted. The Master PIN is an app access gate, not the database key.
  • Biometric App Access: The app can request authentication through Android BiometricPrompt. If an encrypted PIN payload exists, the app attempts to unwrap and verify it. With no saved payload, the current UI can mark the app authenticated after the biometric prompt without verifying the Master PIN. This is an app access convenience, not a guarantee against device or app-process compromise.
  • Phone-to-Phone QR Transfer: Uses AES-GCM with a PBKDF2-HMAC-SHA-256-derived key (600,000 iterations) and a random 16-digit transfer code. The QR and code are displayed separately; protect both.
  • Phone-to-PC Web Drop: Uses ephemeral P-256 ECDH, transcript-bound HKDF-SHA-256, AES-GCM, and a six-digit comparison code over Bluetooth. Compare both screens and approve the transfer on the phone.

3. Permissions Used

  • Biometric / Fingerprint: To authorize optional biometric unlock and Keystore cryptographic operations; available methods and hardware backing depend on the device.
  • Camera: Used to scan pairing and transfer QR codes. Kunjika does not save scanned frames as photos.
  • Bluetooth: Current Bluetooth permissions and legacy Bluetooth permissions on older Android versions are used for a user-initiated Web Drop transfer. Advertising begins after phone authorization and ends when the session ends.
  • Vibrate: Used for haptic feedback in supported transfer and authentication flows.

4. Device and App Integrity Checks

Kunjika can request a token through the Google Play Integrity API using Google Play services. This project has no backend to verify the token, so the feature does not provide a server-validated integrity verdict. Root and emulator checks are advisory and cannot guarantee that a device or app process is uncompromised.

5. Web Companion Privacy (Web Drop)

The Kunjika Web Companion runs its transfer code in the browser and stores the theme preference in browser localStorage. The browser decrypts and displays the selected credential; copying is user-initiated. Closing the view clears visible fields and drops references on a best-effort basis. JavaScript cannot guarantee memory erasure or delete clipboard-manager history. The hosted page is mutable and is not independently authenticated, so use a trusted page source, browser, and computer.

6. Changes to This Policy

We may update our Privacy Policy from time to time. Any changes will be reflected in the updated version of the application and this document.
